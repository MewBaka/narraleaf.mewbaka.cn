<Callout type="info">
    自動プリロードは `0.17.0` から、`preloadGate` は `0.42.0` から、キャッシュ予算は `0.45.0` から、ホスト独自の `PreloadStrategy` は `0.46.0` から利用できます。
</Callout>

プレイヤーは、シーンが描画される前にその資産をフェッチしてデコードします。`0.17.0` 以降、この処理は
ゲームに入ったときではなく、ストーリーが読み込まれた時点で始まるようになりました。組み込み戦略は作業を
複数の帯に分けるため、最初のフレームはそれが必要とする資産だけを待ちます。

<Callout type="warning">
    **`onPreloadComplete` の発火位置が変わりました。** 現在はゲームに入る**前**に発火し、その時点では
    メニューがまだ画面に表示されている可能性があります。「ゲームの内容が画面上にある」という信号には
    `onFirstSceneReady` を使ってください。参照: [どの信号を待つべきか](#which-signal-to-wait-on)。
</Callout>

## プリロードが始まるタイミング

`Player` は、ストーリーが読み込まれた時点ですぐに `story.entryScene` をプリロード対象のシーンとして
登録するため、フェッチはすでに画面にある何かの裏側で行われます。何もマウントされず、アクションも
実行されません。

自動登録が適用されるのは、プリロード中のシーンも、マウント済みのシーンも存在しない場合のみです。
そのため、自ら [preloadScene](/ja/docs/narraleaf-react/core/game/game-state#preloadscene) を呼び出す
ホストは、自分の選択を保持できます。

## 組み込みのプリロード帯

シーンの資産リストは推移的で、そのシーンから到達可能なすべてのシーンの資産セットを含みます。組み込み戦略は作業を 3 つの帯に分け、最初のフレームが必要なものだけを待ちます。

| 帯 | 内容 | 実行方法 |
| --- | --- | --- |
| **Gate** | 開始フレーム。既定ではシーン自身の背景と画像。`preloadGate: "scene"` ではシーンが登録するすべての画像 | ペーシングなし。`event:preloaded.complete` と最初の描画フレームを制御する唯一の帯 |
| **Soon** | 現在のシーンが登録する残りの画像と、遷移先シーンの直接の背景 | 全速で開始し、フレームをブロックしない |
| **Idle** | 到達可能なシーンの先読みセットから、ほかの帯に含まれるものを除いたもの | 最後に実行され、`preloadDelay` でペーシング。新しい時点が来ると破棄 |

`GameConfig.preloadGate` の既定値は `"firstFrame"` で、1 枚の画像だけを待ち、残りはゲームの背後で取得し続けます。登録画像が必要なフレームより後に届くより、開始が遅いほうがよい場合は `"scene"` にします。

`preloadDelay` は idle 帯だけをペーシングします。`preloadAllImages: false` のゲームは従来のアクション予測経路を使います。

## デコード済みビットマップ

Gate と Soon の帯は、画像を表示フレームで描けるようデコード済み要素を保持できます。デコード済みビットマップを保持するかは各プリロード項目が決めます。

idle 帯は既定ではデコード済みビットマップを保持しません。フル解像度のビットマップは 幅 × 高さ × 4 バイトのコストがかかります。

## サウンドのプリロード [#sound-preloading]
現在のシーンのサウンドは、オーディオマネージャーの `preload` を通じて温めます。

```typescript
<Player
    story={story}
    onReady={({ gameState }) => {
        // 音源を再生せずに、フェッチしてデコードし、オーディオキャッシュへ入れる
        void gameState.audioManager.preload(bgm);
    }}
/>
```

- `preload(sound: Sound): Promise<void>` - 音源がオーディオキャッシュに入ったときに resolve します。
  読み込みに失敗した音源は警告としてログに記録されるだけで、代わりに初回再生時に読み込まれるため、
  この Promise は決して reject しません。

<Callout type="warning">
    **この Promise で何かをゲートしないでください。** ブラウザの自動再生ポリシーがユーザー操作によって
    満たされるまでオーディオコンテキストはロックされたままなので、誰もまだ触れていないページでは
    オーディオのウォームアップが保留のまま留まることがあります。エンジン自身の呼び出しは、発行した
    ら結果を気にしない方式です。
</Callout>

自動的に温められるのは現在のシーンのサウンドだけです。先読み対象のシーンの音声は、そのシーン自身の
パスに委ねられます。

## カスタムプリロード戦略 [#custom-preload-strategies]

`GameConfig.preload` は、何をいつ温めるかという組み込みの判断を置き換えます。コンパイル済みのストーリーから次の行を知るホストや、ローカルディスクから資産を配信し、プレイヤーのキャッシュへ複製すべきでないホストに向いています。

```typescript
new Game({
    preload: {
        async plan(moment) {
            if (moment.kind !== "advance") return null;

            return {
                entries: [
                    {type: "image", src: "/art/next.webp", band: "soon", decode: true},
                ],
                audio: [nextVoice],
                video: [nextClip],
                keep: ["/art/next.webp"],
                pin: [],
            };
        },
        async acquire(resource, signal) {
            // acquire を省略すると、プレイヤーが取得とキャッシュを行う
            return {url: resource.src, bytes: 0};
        },
        onMissing(resource) {
            console.warn("Not preloaded:", resource);
        },
    },
});
```

`plan(moment)` は計画、以前の計画を維持する `null`、またはその Promise を返せます。時点は描画直前のシーンか、ストーリーがアクションへ進んだ瞬間です。

計画の内容:

- `entries` は画像だけを含みます。URL、`gate`、`soon`、`idle` のいずれかの帯、画面外でデコードしてビットマップを保持するかを持ちます。
- `audio` は温める `Sound` 要素です。
- `video` は必要になる順の `Video` 要素です。クリップは 1 本ずつバッファリングされ、ストーリー自身が宣言したクリップを計画から解放することはできません。
- `keep` はキャッシュが保持してよい画像 URL の全体です。外側の URL は表示がなくなると解放されます。
- `pin` はメモリ予算から保護する URL で、通常は開始フレームです。

`acquire(resource, signal)` は要素が使う URL を任意で提供します。`{url, bytes, release?}` を返すとキャッシュがバイト数と解放処理を管理し、`null` は温める必要がないことを示します。省略するとプレイヤーの取得と object URL キャッシュを使います。

計画にない内容をステージが表示したとき、`onMissing(resource)` が URL ごとに最大 1 回呼ばれます。コンパイル結果を持つホストは、その画像やクリップを計画すべき行を特定できます。

完全な型は [PreloadStrategy](/ja/docs/narraleaf-react/core/types/PreloadStrategy) を参照してください。

## キャッシュ予算とメモリ [#cache-budgets-and-memory]

プレイヤーのキャッシュには上限があり、`GameConfig` から実行時に読み取られます。

| フィールド | 既定値 | 保持する内容 |
| --- | --- | --- |
| `imageCacheBudgetBytes` | `256 MiB` | object URL が保持する取得済み画像バイト |
| `decodedImageBudgetBytes` | `128 MiB` | デコード済みビットマップ。`幅 × 高さ × 4` バイトで見積もる |

どちらも、現在表示されていない最近使用の少ない項目から破棄します。開始背景とマウント中の画像は固定されます。`Infinity` で上限を外せます。音声は別管理で、再生トークンも現在のシーンも保持していないクリップが解放されます。

[GameState](/ja/docs/narraleaf-react/core/game/game-state) から状態を読めます。

```typescript
const images = liveGame.getGameState()?.getImageCache()?.getStats();
const audio = liveGame.getGameState()?.audioManager.getCacheStats();
liveGame.getGameState()?.audioManager.retainOnly(sceneSounds);
```

[`ImageCacheStats`](/ja/docs/narraleaf-react/core/types/ImageCacheStats) は項目数、取得済みバイト、デコード済み項目数とバイト、固定項目数、現在の予算を返します。`AudioManager.getCacheStats()` はデコード済み音声、読み込み中の音声、PCM バイトを返します。`retainOnly(sounds)` はシーンの音声だけを保持し、残りを解放します。

## どの信号を待つべきか [#which-signal-to-wait-on]
| 信号 | 発火するタイミング |
| --- | --- |
| [onReady](/ja/docs/narraleaf-react/player/player#onready) | `Player` インスタンスが初期化された
とき。`newGame()` はここに置くべきです。これはプリロードや初回レンダリングの保証ではありません。 |
| `onPreloadComplete` | 初回のプリロードパス（gate 帯）が終わったとき。`0.17.0` 以降、これは
**ゲームに入る前**です。メニューがまだ画面にあり、どのシーンもマウントされていない可能性があります。 |
| `onFirstSceneReady` | プリロードパスが終わり、最初のシーンコンポーネントがマウントされ、**さらに**
ブラウザがそれを描画するフレームを 1 回消化した状態。これが「内容が画面上にある」という信号です。 |

後者の 2 つは `Player` の prop としても `Game` のメソッドとしても存在し、それぞれゲームのライフサイクル
内で最大 1 回だけ発火します。

```tsx
<Player
    story={story}
    onReady={({ liveGame }) => liveGame.newGame()}
    onPreloadComplete={() => setLoadingBarDone(true)}   // メニューがまだ表示されている場合がある
    onFirstSceneReady={() => setLoadingOverlay(false)}  // シーンが描画された
/>
```

```typescript
// Player 要素以外のコードのための、同じ時点。
await game.whenPreloadComplete();
await game.whenFirstSceneReady();

game.isPreloadComplete();
game.isFirstSceneReady();
```

両方の時点それぞれの `on*`、`once*`、`when*`、`is*` を含む完全なリスナー一覧は
[Game](/ja/docs/narraleaf-react/core/game/game#onpreloadcomplete) を参照してください。

### 0.16 以前からのアップグレード

<Callout type="warning">
    **これは挙動の破壊的変更であり、新しい API ではありません。** `onPreloadComplete`、
    `oncePreloadComplete`、`whenPreloadComplete()`、`event:preloaded.complete` はいずれも、
    `newGame()` がシーンをマウントした後ではなく、ゲームに入る前に発火するようになりました。
    名前とシグネチャは変わっていないため、コンパイルが失敗することはありません。そして、そこで
    ローディング画面を隠していたホストは、今やマウントされていないステージを露出させることに
    なります。

    - **読み込みステップの制御**（プログレスバーや、資産がまだダウンロード中は押せないようにする
      「開始」ボタンなど）に使っていた場合: 変更は不要です。
    - **「ゲームの内容が画面上にある」**ことを意味させていた場合: `onFirstSceneReady` /
      `whenFirstSceneReady()` に切り替えてください。これらは変更されておらず、依然としてマウント
      済みのシーンを必要とします。

    `preloadComplete` リスナーが受け取る `ctx.scene` は、現在ではマウント済みのシーンではなく
    *プリロード中の*シーンである場合があります。
</Callout>

`onPreloadedReady` は非推奨であり、`onPreloadComplete` の使用が推奨されます。

## シーンを自分でプリロードする

入口シーン以外のシーンを温めるには、それを指定します。プレイヤーがどのシーンへ再開しようとしているかを
知っているセーブスロット画面は、次のように呼び出せます。

```typescript
gameState.preloadScene(scene);   // または Story を渡すと、その入口シーンが使われる
```

Player が入口シーンを登録する前にこれを呼び出すと、自動登録は行われません。

## 設定

以下は [GameConfig](/ja/docs/narraleaf-react/core/types/GameConfig) 上にあります。

- `preloadAllImages`（デフォルト `true`）- 組み込みのシーンプリロードを実行するかどうか。`false` の場合、
  プレイヤーは次の `maxPreloadActions` 個のアクションを予測し、代わりにそのソースをプリロードします。
- `preloadConcurrency`（デフォルト `5`）- 同時にフェッチする画像の数。
- `preloadDelay`（デフォルト `100`）- idle 帯のバッチ間のペーシング。
- `waitForPreload`（デフォルト `true`）- gate 帯が終わるまでプレイヤーの表示を保留する。
- `forceClearCache`（デフォルト `false`）- シーンが変わったときに画像キャッシュをクリアする。
- `maxPreloadActions`（デフォルト `10`）- `preloadAllImages: false` の経路が何アクション先まで
  予測するか。
- `preloadGate`（デフォルト `"firstFrame"`）- gate が開始フレームを待つか、シーンが登録するすべての画像を待つか。
- `preload` - カスタム `PreloadStrategy`。未設定なら上記の組み込み帯を使います。
- `imageCacheBudgetBytes`（デフォルト `256 MiB`）- キャッシュが保持できる取得済み画像バイト。
- `decodedImageBudgetBytes`（デフォルト `128 MiB`）- キャッシュが保持できるデコード済みビットマップバイト。
