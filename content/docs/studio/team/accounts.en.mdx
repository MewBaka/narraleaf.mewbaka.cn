---
title: Accounts and access
description: Create Team accounts, grant a project role or area template, and take access away.
---

Every account is made by an operator. There is no public registration. The first account is created with `nlteam init`; after that, operators create accounts in the web console or with `nlteam user create`.

## Signing in

Studio normally signs in through the browser with OAuth and PKCE. A machine without a browser uses the device flow and enters the code at `/console/device`.

The server can require two-step sign-in, require SSO, issue API tokens and send password-reset links. Password sign-in remains for Studio builds that predate browser sign-in.

Every signed-in Studio is a device. Its owner can end it from the console, and an operator can end every device of an account. Studio 2.0 keeps the signed-in account in the title bar, including while the server is away.

## Creating an account

On the server:

```sh
printf '%s' 'their password' | nlteam user create bob --root /srv/team
```

From a machine signed in as an operator:

```sh
nlteam login team.example.com:54080 ada < password.txt
printf '%s' 'their password' | nlteam user create bob --server team.example.com:54080
```

Passwords come from standard input, never an argument. An operator can issue a sign-in token instead:

```sh
nlteam token mint bob --server team.example.com:54080
```

## Operators

The `admin` group manages accounts, projects, settings, signing keys, storage and backups. `nlteam init` puts the first account in it.

```sh
nlteam user grant-admin bob --server team.example.com:54080
nlteam user revoke-admin bob --server team.example.com:54080
```

The console can edit, lock and delete accounts. The last operator cannot remove their own access.

## Project roles and areas

Access is per project. Each member has one role:

| Role | May |
| --- | --- |
| Owner | Change project settings and members, edit every area, save or restore versions as the project allows, and remove the project from the list. |
| Editor | Edit the areas granted to them, and save or restore versions where the project allows editors to do so. |
| Reviewer | Read, comment and take part in review; edit no project content. |
| Viewer | Read and record the collaboration their account is allowed; edit no project content. |

An owner or operator changes membership in the console's project settings or through `projects.members.set` and `projects.members.remove`. There is no `nlteam` command for membership yet.

Editors can be limited to story, characters, assets, UI, localization or game config. Anything Team does not recognise counts as game config, so a new kind of file is guarded by default. Restoring a version touches every area and needs all six.

Permission templates provide a role and area set: owner, editor, writer, translator, artist, engineer, reviewer or viewer. A project can also accept access requests, decided by its owners or an operator.

## What Studio 2.0 shows

A project the account has no role in is not listed. The launcher marks team projects and keeps their server settings outside the project. Studio tells the author when their role is read-only and shows the server round trip in the status bar.

## Studio settings on the server

When Studio is signed in to a Team server, **Settings → Transfer** offers **Back up to Team** and **Restore from Team**. The backup carries the same settings document as an exported settings file. A restore is checked and previewed before anything changes.

A server can refuse the operation through an account policy, a document that is too large, or a server build that does not support it; each refusal has its own message.

## Taking access away

Change the project role or remove the member. To stop the account everywhere:

```sh
nlteam user disable ada --server team.example.com:54080
nlteam user revoke-tokens ada --server team.example.com:54080
```

**`disable`** stops the account and refuses a new sign-in. **`revoke-tokens`** refuses every token already issued but lets the account sign in again with the same password. Both take effect on Studio's next call.

<Callout type="warning">
A project data connection already open is checked by the version-control server until its repository token expires, fifteen minutes by default. Ending it sooner means rotating the signing key and then retiring the old one, which signs everyone out.
</Callout>

A disabled account can be enabled again with `nlteam user enable ada`. The console can also lock an account temporarily or delete it.

## Listing what is there

```sh
nlteam user list --server team.example.com:54080
nlteam project list --server team.example.com:54080
nlteam status --server team.example.com:54080
nlteam audit --refused --server team.example.com:54080
```

`audit` reads access decisions newest first. `--refused` prints refusals only. The console shows the same record with filters, beside account and storage administration.
