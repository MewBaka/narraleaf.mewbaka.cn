---
title: アカウントとアクセス
description: Team アカウントを作成し、プロジェクトの役割や領域テンプレートを付与し、アクセスを取り消す
---

すべてのアカウントは管理者が作成します。一般公開の登録はありません。最初のアカウントは `nlteam init` で作り、その後は Web コンソールまたは `nlteam user create` で作成します。

## サインイン

Studio は通常、OAuth と PKCE を使ってブラウザからサインインします。ブラウザのないマシンではデバイスフローを使い、`/console/device` にコードを入力します。

サーバーは 2 段階サインインや SSO を必須にでき、API トークンを発行し、パスワード再設定リンクを送れます。ブラウザサインイン以前の Studio にはパスワードサインインも残っています。

サインインした Studio はそれぞれ 1 つのデバイスです。所有者はコンソールから終了でき、管理者は 1 つのアカウントの全デバイスを終了できます。Studio 2.0 はサインイン中のアカウントをタイトルバーに表示し、サーバーが応答しない間も保持します。

## アカウントを作成する

サーバー上で:

```sh
printf '%s' 'their password' | nlteam user create bob --root /srv/team
```

管理者としてサインイン済みのマシンから:

```sh
nlteam login team.example.com:54080 ada < password.txt
printf '%s' 'their password' | nlteam user create bob --server team.example.com:54080
```

パスワードは標準入力から読み、引数には書きません。パスワードの代わりにサインイントークンを発行できます。

```sh
nlteam token mint bob --server team.example.com:54080
```

## 管理者

`admin` グループはアカウント、プロジェクト、設定、署名キー、ストレージ、バックアップを管理します。`nlteam init` は最初のアカウントをこのグループに入れます。

```sh
nlteam user grant-admin bob --server team.example.com:54080
nlteam user revoke-admin bob --server team.example.com:54080
```

コンソールではアカウントの編集、ロック、削除ができます。最後の管理者は自分のアクセスを取り除けません。

## プロジェクトの役割と領域

アクセスはプロジェクト単位です。各メンバーは 1 つの役割を持ちます。

| 役割 | できること |
| --- | --- |
| 所有者 | プロジェクト設定とメンバーを変更し、すべての領域を編集し、プロジェクトの設定に従ってバージョンを保存・復元し、プロジェクトを一覧から外す |
| 編集者 | 許可された領域を編集し、プロジェクトが許す場合はバージョンを保存・復元する |
| レビュー担当 | 閲覧、コメント、レビューへの参加。プロジェクト内容は編集しない |
| 閲覧者 | 閲覧と、自分のアカウントで許可された共同作業の記録。プロジェクト内容は編集しない |

所有者または管理者は、コンソールのプロジェクト設定、または `projects.members.set` と `projects.members.remove` でメンバーを変更します。メンバー変更用の `nlteam` コマンドはまだありません。

編集者はストーリー、キャラクター、アセット、UI、ローカライズ、ゲーム設定に制限できます。Team が認識しないパスはゲーム設定として扱うため、新しい種類のファイルは既定で保護されます。バージョンの復元は全領域に触れるため、6 つすべての権限が必要です。

権限テンプレートは役割と領域の組を付与します。所有者、編集者、ライター、翻訳者、アーティスト、エンジニア、レビュー担当、閲覧者があります。プロジェクトはアクセス申請も受け付け、所有者または管理者が判断します。

## Studio 2.0 での表示

アカウントが役割を持たないプロジェクトは表示されません。ランチャーはチームプロジェクトを示し、サーバー設定をプロジェクトの外に保存します。役割が読み取り専用の場合は Studio が明示し、ステータスバーがサーバーとの往復を表示します。

## サーバー上の Studio 設定

Studio が Team サーバーにサインインしていると、**Settings → Transfer** に **Back up to Team** と **Restore from Team** が表示されます。バックアップは書き出した設定ファイルと同じ設定ドキュメントを運びます。復元は内容を確認し、プレビューしてから変更します。

サーバーはアカウントポリシー、ドキュメントが大きすぎる場合、対応していないサーバーバージョンなどの理由で操作を拒否でき、それぞれに専用のメッセージがあります。

## アクセスを取り消す

プロジェクトの役割を変更するか、メンバーから外します。アカウント全体を止めるには:

```sh
nlteam user disable ada --server team.example.com:54080
nlteam user revoke-tokens ada --server team.example.com:54080
```

**`disable`** はアカウントを停止し、再サインインを拒否します。**`revoke-tokens`** は発行済みの全トークンを拒否しますが、同じパスワードで再びサインインできます。どちらも Studio の次の呼び出しから効きます。

<Callout type="warning">
すでに開いているプロジェクトデータ接続は、リポジトリトークンが期限切れになるまでバージョン管理サーバーが確認します。既定は 15 分です。それより早く終えるには署名キーをローテーションしてから古いキーを廃止します。これで全員が再サインインすることになります。
</Callout>

停止したアカウントは `nlteam user enable ada` で戻せます。コンソールでは一時的なロックや削除も行えます。

## 現在の内容を一覧する

```sh
nlteam user list --server team.example.com:54080
nlteam project list --server team.example.com:54080
nlteam status --server team.example.com:54080
nlteam audit --refused --server team.example.com:54080
```

`audit` はアクセス判断を新しい順に読みます。`--refused` は拒否だけを表示します。コンソールでも同じ記録をフィルター付きで表示し、アカウントとストレージの管理を行えます。
