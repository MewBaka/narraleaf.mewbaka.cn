Team サーバーは、アカウント、プロジェクトのドキュメント、バージョン、共同作業の記録を保持します。完全なモデルと受け入れたリスクはリポジトリの[セキュリティドキュメント](https://github.com/NarraLeaf/NarraLeaf-Team/blob/main/docs/security.md)にあります。このページはデプロイの観点からまとめたものです。

## アクセスはプロジェクト単位

各プロジェクトにはメンバーがいて、各メンバーは所有者、編集者、レビュー担当、閲覧者のいずれか 1 つの役割を持ちます。呼び出し元が役割を持たないプロジェクトは、その人にとって存在しません。そのプロジェクトに関するメソッドとトピックは「権限がない」ではなく「見つからない」と答えます。

所有者と編集者はプロジェクトのリポジトリを開けます。レビュー担当と閲覧者は開けず、Team を通してプロジェクトを読みます。バージョン管理サーバーは読み取りと書き込みを区別できないため、書き込めない役割はリポジトリも開けません。

編集者はストーリー、キャラクター、アセット、UI、ローカライズ、ゲーム設定に制限できます。Team は変更が到達するファイルから領域を決め、認識しないものはゲーム設定として扱います。バージョンの復元は全領域に触れるため、6 つすべてが必要です。

管理者はすべてのプロジェクトの所有者です。新しいプロジェクトは作成者を所有者とし、ほかのアカウントを編集者にします。新しいアカウントも既存のすべてのプロジェクトで編集者になるため、0.1.0 からのアップグレードは所有者が絞るまで以前と同じように動きます。アップグレード後は重要なプロジェクトのメンバーを確認してください。

プロジェクトを一覧から外せるのは所有者または管理者だけです。リポジトリは保管庫に残り、登録行、スレッド、コメントが削除されます。再登録する可能性があるなら、外す前にリポジトリ id を記録してください。

## 接続が何に支えられているか

クライアントの発言はすべて 1 つのポートと 1 つの証明書を通ります。組織が証明書を用意しない場合、Team が自分で発行します。人が信頼する接続とは別の経路で一度だけフィンガープリントを照合します。Studio は見せられた認証局を保存し、後で別の認証局が示されると拒否します。

Web コンソールも同じオリジンと証明書で動きます。セッションは `HttpOnly` の同一オリジン Cookie で、アカウントのデバイス一覧から取り消せます。他人が書いた文字を表示するページには、インラインスクリプトと第三者オリジンを許可しないポリシーを適用します。

Studio は PKCE とループバックリダイレクトを使う OAuth、またはデバイスフローでサインインできます。古い Studio のためにパスワード経路も残っています。サーバーは 2 段階サインインや SSO を必須にでき、API トークンとパスワード再設定リンクを提供できます。

## トークンが証明するもの

サインイントークンは Team の呼び出しごとに再確認されます。公開鍵に対する署名、発行者、audience、有効期限、アカウントが存在して停止・ロックされていないこと、トークンが最後のアクセス失効より前ではないことを調べます。

リポジトリトークンはデータ接続で提示されます。バージョン管理サーバーがそこで署名と有効期限を確認し、期限が切れるまで Team に問い合わせません。既定の有効期間は 15 分で、すでに開いているデータ接続が役割の取り消し後に存続できる最大時間です。

## 誰が何をできるか

| 保持者 | アクセスできるもの |
| --- | --- |
| プロジェクトの閲覧者・レビュー担当 | 役割に応じて Team 経由でファイル、バージョン、コメント、レビュー。リポジトリは開けない |
| プロジェクトの編集者 | 許可された領域。全領域を持つ場合だけリポジトリを開ける |
| プロジェクトの所有者 | そのプロジェクトのすべて。メンバー、設定、バージョン、一覧からの削除を含む |
| 管理者 | すべてのプロジェクト、アカウント、設定、署名キー、ストレージ、バックアップ、監査記録 |
| ストレージルートを保持する人 | すべて。任意のアカウントのトークンを発行できる鍵も含む |

最後の行は欠陥ではありません。サーバーは自分のディレクトリからしか復旧できないため、そのディレクトリこそ、マシンの権限、ディスク暗号化、バックアップで守るべきものです。

## 記録されるもの

リポジトリへのアクセス判断はすべて記録され、コンソールと `nlteam audit` で読み戻せます。共同作業の記録には作者と時刻が残り、プロジェクトの作業は実際に行った人の名義になります。

## 脆弱性を報告する

[GitHub のセキュリティアドバイザリフォーム](https://github.com/NarraLeaf/NarraLeaf-Team/security/advisories/new)から非公開で報告してください。セキュリティ問題の公開 issue は作らないでください。
