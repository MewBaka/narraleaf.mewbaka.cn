Team 服务器保存账号、项目文档、版本和协作记录。完整模型与已接受的风险见仓库中的[安全文档](https://github.com/NarraLeaf/NarraLeaf-Team/blob/main/docs/security.md)。本页从部署角度说明。

## 访问权按项目划分

每个项目都有成员，每个成员只有一个角色：所有者、编辑者、审阅者或查看者。调用者没有角色的项目，对他而言就不存在：涉及它的每个方法和主题都回答「找不到」，而不是「无权访问」。

所有者与编辑者可以打开项目仓库；审阅者与查看者不能，他们通过 Team 读取项目。版本控制服务器无法区分读取与写入，因此不能写入的角色也不能打开仓库。

编辑者可以限制在剧情、角色、资产、界面、本地化或游戏配置。Team 根据修改最终到达的文件判断区域，无法识别的路径按游戏配置处理。恢复版本会改动所有区域，需要全部六项权限。

运维是每个项目的所有者。新项目以创建者为所有者，其余账号默认成为编辑者。新账号默认成为所有已有项目的编辑者，因此从 0.1.0 升级后，行为与旧服务器相同，直到项目所有者收窄权限。升级后应检查敏感项目的成员。

只有项目所有者或运维可以把项目移出列表。仓库仍留在存储中；注册表中的一行以及挂在它上面的讨论和批注会被删除。如果之后还要重新登记项目，请在移出前记下仓库 id。

## 连接建立在什么之上

客户端发送的一切都到达同一个端口，背后是同一张证书。除非组织提供了证书，服务器会自己签发；指纹由人通过这条连接之外的渠道核对一次。Studio 会保存见过的证书颁发机构，之后拒绝不同的机构。

Web 控制台使用同一个源和证书。它的会话是 `HttpOnly`、同源的 Cookie，可以从账号的设备列表中撤销。展示他人所写文字的页面使用不允许内联脚本和第三方源的策略。

Studio 可以通过带 PKCE、重定向到回环地址的 OAuth 登录，也可以使用设备码流程。旧版 Studio 仍可使用密码。服务器可以要求两步验证、要求 SSO、签发 API 令牌并使用密码重置链接。

## 令牌能证明什么

每次 Team 调用都会重新检查登录令牌：对照已发布密钥的签名、签发者、受众、有效期、账号是否仍然存在且未被停用或锁定，以及令牌是否早于该账号最近一次访问撤销。

仓库令牌在数据连接上出示。版本控制服务器检查签名与有效期，在此之前不再询问 Team。默认有效期为十五分钟，这也是已经打开的数据连接在角色被撤销后最长能继续多久。

## 谁能做什么

| 持有者 | 可以访问 |
| --- | --- |
| 项目查看者或审阅者 | 通过 Team 访问项目文件、版本、批注与审阅，范围由角色决定；不能打开仓库 |
| 项目编辑者 | 获准的区域；只有拥有全部区域时才能打开仓库 |
| 项目所有者 | 该项目中的全部内容，包括成员、设置、版本和移出列表 |
| 运维 | 所有项目、账号、设置、签名密钥、存储、备份和审计记录 |
| 持有存储根目录的人 | 全部内容，包括为任何账号签发令牌的密钥 |

最后一行不是缺口。服务器只能从自己的目录恢复，所以那个目录要用机器权限、磁盘加密和备份去保护。

## 记录了什么

每一次仓库访问决定都会记录，控制台与 `nlteam audit` 可以读回。协作记录带有作者与时间，项目工作记在实际完成它的人名下。
