title: Connecting Studio

An author is given the server's address, an account, and the certificate fingerprint. Everything else is exchanged between Studio and the server.

## Adding a server

<Steps>

<Step>

### Open Team in the launcher

**Team** is one of the launcher entries. Servers this installation has connected to are listed there.

<Figure
    src="/static/img/docs/team/en/studio-team-empty.webp"
    alt="The Team page of the launcher before any server is added"
/>

</Step>

<Step>

### Add a server

**Add a server** takes an address in the form `nlteam://team.example.com:54080`. A link such as `narraleaf://team/connect?server=https://team.example.com:54080` opens the same dialog with the address filled in. Port `41337` must also be reachable for project data.

<Figure
    src="/static/img/docs/team/en/studio-add-server.webp"
    alt="The Add server window with an nlteam:// address filled in"
/>

</Step>

<Step>

### Trust the certificate

A server issues its own authority unless the organization supplied a trusted certificate. Compare the fingerprint shown by Studio with the one from `nlteam status`, then accept it. Studio keeps that authority and refuses a different one later. The operating system may ask for permission while it is installed.

</Step>

<Step>

### Sign in

Choose **Sign in with browser** when the server offers it. Studio opens the server's console, where the account signs in and approves the device. If the machine cannot open a browser, use the device flow and enter the code at `/console/device` on another device.

Password sign-in remains for older Studio builds. A server may require two-step sign-in or SSO.

<Figure
    src="/static/img/docs/team/en/studio-sign-in.webp"
    alt="Choosing how to sign in once the server is confirmed: the browser by default, with the device code, username and password, and access token under other methods"
/>

</Step>

</Steps>

The server then appears under **Team** with the projects the account may see. A project without a role for this account is not listed.

<Figure
    src="/static/img/docs/team/en/studio-team-server.webp"
    alt="After signing in, the Team page shows the server, its address and the account, with to-dos, active projects and members"
/>

## Getting a project

Open the server and its **Projects** tab. A project can be **Get** (copy it to this machine) or **Open** (open a copy already on this machine).

A project taken this way stays connected to the server. The launcher marks it as a team project, and its server settings are kept outside the project.

<Figure
    src="/static/img/docs/team/en/studio-launcher-team.webp"

## Working in Studio 2.0

Team is the authority for the current documents. Studio sends an edit, Team applies it with the same document kernel, numbers the result and tells every connected window. A window that was offline keeps its work and replays it on reconnect.

<Figure
    src="/static/img/docs/team/en/studio-team-workspace.webp"
    alt="A team project in the workspace: the history rail on the left says it is live, the title bar shows the account, and the status bar shows the server and the round trip"
/>

The Team history rail shows versions, conflicts and reconnection. Offline edits that cannot be applied are listed as conflicts and the author chooses what to apply. Work in progress is never silently replaced by the server.

The title bar shows the signed-in account, including while the server is away. The status bar shows the round trip to the server. A role that cannot edit says so before the editor accepts a change.

Each connection agrees the document kernel first. If Studio and Team use different kernels, Team refuses document edits and events for that project, and Studio keeps working offline rather than writing a format the other side reads differently.

## Review and collaboration

Row comments, suggested edits, to-dos, reviews, asset and language requests, approvals and asset locks stay inside the project's membership. A comment follows the row it discusses. A to-do can be completed through a commit or a saved Team version.

The web console can read the same threads, files and versions. It records work around the project; it does not become a second editor for project content.

## Signing out

Studio's **NarraLeaf Team** settings list the servers this installation is connected to and the account used for each. Removing a server forgets its token and authority. Copies already on this machine are untouched. The console also lists an account's devices and can end any one of them.

## When a server does not answer

| What Studio reports | What it means |
| --- | --- |
| This server did not answer. | The address is wrong, or 54080 is not reachable. |
| The server at that address is not a NarraLeaf Team server. | Something answered, but it was not Team. |
| This server refused the account signed in here. | The account was disabled, locked, or its tokens were revoked. |
| This server cannot be asked from this installation. | The stored token is gone. Add the server again. |
| The server's document kernel is different. | Studio and Team cannot safely edit this project's documents together. Update the newer side or keep working offline. |
| Your role in this project is read-only. | The role allows reading or review, not project edits. Ask an owner for another role. |

A project that opens but cannot send an edit usually has a role without that area, a kernel mismatch, or a stale server address. The console's project settings and `nlteam status` answer those cases.
