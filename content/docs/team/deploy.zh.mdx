Team 服务器运行在一台机器上，它拥有的一切都保存在一个目录下。容器镜像包含版本控制服务器、文档内核和 Web 控制台。

## 使用 Docker

写一个 `compose.yaml`。把 `NLTEAM_HOSTNAME` 改成使用者访问时使用的名字；它会写进证书与每个令牌的受众。

```yaml
services:
  team:
    image: ghcr.io/narraleaf/team:1.0.5
    restart: unless-stopped
    environment:
      NLTEAM_HOSTNAME: team.example.com
    ports:
      - "54080:54080"
      - "41337:41337/tcp"
      - "41337:41337/udp"
    volumes:
      - team:/var/lib/nlteam
volumes:
  team:
```

<Steps>

<Step>

### 启动服务器

```sh
docker compose up -d
```

镜像为 `linux/amd64`。首次启动不会下载任何东西。

</Step>

<Step>

### 创建第一个账号

把口令写进一个只有该口令的文件，至少十个字符。

```sh
printf '%s' 'a password of your own' > admin-password
docker compose exec -T team nlteam init ada < admin-password
rm admin-password
```

`init` 只运行一次，把第一个账号放进 `admin` 组。服务器上已有账号后会拒绝。口令从标准输入读取，因此不会出现在进程列表或 shell 历史中。

第一个账号也可以在浏览器中创建：服务器还没有账号时，日志（`docker compose logs team`）会给出 `/console/setup` 地址和设置码。

</Step>

<Step>

### 读取地址与指纹

```sh
docker compose exec team nlteam status
```

`sign in` 一行给出端点地址，另一行给出证书指纹。请通过即将建立的连接之外的渠道发送指纹。

</Step>

<Step>

### 打开 Web 控制台

访问 `https://<服务器>:54080/console/`。浏览器必须信任证书。使用 Team 自己的证书颁发机构时，要在每台用浏览器打开控制台的机器上安装它：即存储根目录下的 `tls/ca.crt`，`nlteam trust` 也会打印它。`nlteam trust --install` 只会把它安装到服务器本机。使用浏览器已信任的机构签发的证书时不需要额外步骤。

    alt="新服务器的 /console/setup：输入 nlteam up 打印的设置码，然后创建管理员并设置团队名称"
/>

</Step>

</Steps>

交给作者的是主机名加端口，写作 `nlteam://team.example.com:54080`。`status` 给出的 `https://` URL 是登录端点；Studio 的添加服务器窗口接受 `nlteam://` 形式。

## 端口

| 端口 | 作者的机器能否访问 | 承载 |
| --- | --- | --- |
| 54080 | 能 | 登录、Studio 会话、Web 控制台与项目 API |
| 41337 | 能，TCP 与 UDP | 项目数据 |
| 41339 | 否 | 版本控制服务器的健康检查 |
| 41400 | 否 | 服务器的签名密钥 |

41337 的两半都要发布。QUIC 使用 UDP，只开放 TCP 会让这样的客户端一直等待。其他监听器绑定在回环地址上。

## 不使用 Docker

`nlteam` 包尚未发布。请从检出构建：

```sh
git clone https://github.com/NarraLeaf/NarraLeaf-Team.git
cd NarraLeaf-Team
npm install && npm run build && npm link
nlteam up --root /srv/team --hostname team.example.com
```

`up` 会安装版本控制服务器、写好配置、启动并一直运行到被中断。其余命令在第二个终端运行。

```sh
printf '%s' 'a password of your own' | nlteam init ada --root /srv/team
nlteam status --root /srv/team
```

需要 Node.js 24 或更新版本，运行在 64 位 Linux、Windows 或 Apple 芯片上。

## 使用自有证书

组织已有对应名字的证书时，把它交给服务器。签发者已在每台机器上受信任，因此不需要核对指纹。

```yaml
    environment:
      NLTEAM_HOSTNAME: team.example.com
      NLTEAM_TLS_CERT: /etc/nlteam/tls/fullchain.pem
      NLTEAM_TLS_KEY: /etc/nlteam/tls/privkey.pem
    volumes:
      - team:/var/lib/nlteam
      - ./tls:/etc/nlteam/tls:ro
```

两个值同时给出或都不给出，私钥不能带口令。更换证书后重启即可。Team 仍会向回环地址和自有证书未覆盖的名字出示自己的证书。

## 更新

先修改 `compose.yaml` 中的镜像标签，然后：

```sh
docker compose pull
docker compose up -d
```

数据库会在启动时迁移，证书颁发机构会保留，因此不需要重新信任服务器。请固定镜像标签，不要使用 `latest`；`latest` 与 `develop` 可能在没人重启的部署下变化。

<Callout type="warning">
从 1.0.5 起登录端口是 54080，1.0.0 使用 41402。从 1.0.0 升级时，把发布的端口改成 `54080:54080` 并把新地址告诉作者；或者设置 `NLTEAM_AUTH_TLS_PORT: "41402"` 并发布 `41402:41402`，保留原端口。
</Callout>

## 备份

`/var/lib/nlteam` 或 `--root` 指定的目录保存账号、项目、文档日志、签名密钥、证书颁发机构和仓库存储。

```sh
nlteam backup --root /srv/team
```

`backup` 写出 `<root>/backups/nlteam-backup-YYYYMMDD-HHMMSS.tar.gz`（UTC 时间），服务器运行时也可以执行。容器中写作 `docker compose exec team nlteam backup`。控制台的存储页面也能创建备份；后台的 `backup.every_hours`（默认关闭）设置定时备份，`backup.keep`（默认 7）设置保留份数。根目录下的备份与它保护的数据在同一块磁盘上，请另外复制一份。

恢复前先停止服务器。根目录里已有文件时，`restore` 需要 `--force`，原有内容会移到 `<root>/before-restore-YYYYMMDD-HHMMSS/`，而不是被删除。备份文件可以就是该根目录自己的备份。

```sh
nlteam restore /srv/team/backups/nlteam-backup-YYYYMMDD-HHMMSS.tar.gz --root /srv/team --force
```

使用 Docker 时，在挂载同一个卷的一次性容器里恢复。镜像的入口是 `nlteam`，所以命令从 `restore` 开始：

```sh
docker compose stop team
docker compose run --rm team restore /var/lib/nlteam/backups/nlteam-backup-YYYYMMDD-HHMMSS.tar.gz --force
docker compose start team
```

确认恢复后的服务器正常后，删除 `before-restore-…` 目录。
